# Game modes and movement maps

Native CS2 modes (deathmatch, arms race, wingman, casual, aim) and movement courses (surf, bhop, kz) as `map_edit` operations, plus mode-aware play tests. Code: `modes.py`, `ext/modes.py`; tools `mode_setup`, `playtest(kind="mode"|"course")`.

## How it works

**Modes.** CS2 picks the mode on the server before the map loads (`game_type`/`game_mode`: casual 0/0, wingman 0/2, deathmatch 1/2, arms race 1/0), so `mode_setup` only prepares the map and returns the launch command; it never sets global cvars. `add_mode` (names `c2_*`) takes `mode`, optional `spawns` (2..128 feet points; otherwise free floor from the layout), `equip` and `weapon`. Deathmatch gets `info_deathmatch_spawn` and `info_map_parameters.disableautogenerateddmspawns = 1`; arms race team spawns 128 apart; T/CT spawns stay for joining; nav seeds for bots; a generated script attaches `game_player_equip` after `OnPlayerReset` and reports kills and resets. The group keeps `cs2map_mode`; `check_map` uses it to drop rules the mode does not use.

**Movement.** `add_surf_ramp` is a closed wedge at 45–60° across its width; `add_bhop_platforms` boxes with a gap and rise; `add_movement_course` start, finish and checkpoint triggers, a fall teleport and a base destination, with a script that keeps each player's checkpoint and time (log marker `C2_TIMER`; optional HUD). `add_arena` is one room with ten spawns per team on opposite walls, mirrored cover and equipment, plus `add_mode("aim")`.

**Tests.** `playtest(kind="mode")` snapshots game type/mode, freeze, respawn, warmup, team limits, movement and bot cvars, sets `mp_freezetime 0` before the reload, verifies it after, plays with bots and restores the snapshot after `mcp_idle`, reading every value back. `playtest(kind="course")` triggers the real `OnStartTouch` of the course with setup teleports: timer, checkpoints and returns are proven; riding a surf ramp by hand stays a manual check.

## Why it is built this way

- A batch with `add_mode` runs as a preview first, so a late parameter error never leaves a written script.
- A kill or a respawn is an observed event: `mode_ok = false` without kills is reported, not hidden.
