# Game modes and movement courses

| Task | Take |
| --- | --- |
| Deathmatch, Arms Race, Wingman, casual, surf, bhop, kz, aim | `mode_setup` + `map_edit` `add_mode` |
| Arena, surf ramps, bhop platforms, timed courses | `add_arena`, `add_surf_ramp`, `add_bhop_platforms`, `add_movement_course` |
| Test | `playtest(kind="mode")`, `playtest(kind="course")` |

The C2 extension adds map-local setup for native CS2 rules and small movement/aim courses. All coordinates are CS2 units (inches), with player feet at `z`; place spawns 8 units above a floor. Native rules are selected by `game_type` and `game_mode` **before** the map is loaded; authoring does not change the running server. Use `playtest(kind="mode")` for a bounded test; it restores the previous console settings and unloads to `mcp_idle`.

## Native mode setup

```json
{"map":"c2_dm","mode":"deathmatch"}
```

`mode_setup(map, mode)` returns the native launch command and adds the required map entities/script. Accepted modes are `deathmatch` (1/2), `armsrace` (1/0), `wingman` (0/2), `casual` (0/0), and local course modes `surf`, `bhop`, `kz`, `aim` (3/0). Deathmatch receives `info_deathmatch_spawn` points and disables autogenerated points. Arms Race receives 128-unit-separated `info_armsrace_terrorist`/`info_armsrace_counterterrorist` points. Wingman expects one bombsite from `add_comp_plan(mode="wingman")`. Casual keeps normal team spawns. A generated `point_script` records real kill and player-reset events and can report them through `RunScriptInput Report`.

`playtest(map, kind="mode", bots=10, seconds=30)` accepts 2–20 bots and 5–60 seconds. It checks both teams, nav, movement, console errors, and for deathmatch/armsrace a real kill followed by `OnPlayerReset`; `mode_ok=false` is an honest result when the bounded run did not observe one. It returns the native pair, event counters, a diagnostic frame, and `settings_restored`.

The playtest sets `mp_freezetime 0` before the native map reload and again after
the map config is active. It reports `mp_freezetime_during_test=0`, then restores
the complete saved convar snapshot in `finally` and verifies every value.
`game_screenshot` waits for a live round in the same way.
`check_map` knows the mode written by `add_mode`: for deathmatch, Arms Race,
surf, bhop, kz and aim it skips the defuse-only rules (buyzone, bombsite), lists
them in `inapplicable_core_checks` and keeps every geometry and entity error.

## Movement operations

`map_edit` operations:

```json
{"op":"add_surf_ramp","origin":[0,0,0],"length":1024,"width":256,"angle":55,"side":"+y"}
{"op":"add_bhop_platforms","origin":[0,512,128],"count":8,"size":[96,96,16],"gap":64,"rise":12}
```

`add_surf_ramp` creates a solid wedge 45–60 degrees, with a configurable stock material. `length` is travel direction, `width` is the cross-slope span. `add_bhop_platforms` creates 1–64 solid platforms with a 16–256 unit gap and a -48..48 unit rise per jump.

`add_movement_course` creates start, finish, checkpoint and fall triggers, an `info_teleport_destination`, and a self-contained `cs_script`. Start begins an engine-time timer; checkpoint touch updates the player's last destination; finish prints `C2_TIMER <name> ... finish seconds=...`; falling returns the same player to the last checkpoint with zero velocity. `mode` is `surf`, `bhop`, or `kz`; `spawn` is required and checkpoints are `{mins,maxs,destination}`. HUD uses an existing compiled `panorama/layout/custom_game/*.vxml`; pass `hud_layout:null` for console-only timing.

`playtest(map, kind="course", timeout=60)` drives those trigger events with bounded
setup teleports (`timeout` 15–90 s), checks the `C2_TIMER` start/checkpoint/
return/finish lines and captures two HUD frames. It proves trigger and timer
logic; it does not claim that a human physically surfed or bhopped the route.
Generated script and entity names must use the `c2_` namespace; changing an
already referenced script name is refused until the map is recreated.

`add_arena` creates an axis-aligned 1v1/aim room (minimum 768×512×128), mirrored T/CT spawn lines, optional cover boxes, a `game_player_equip`, and the aim mode script. `weapon` is a `weapon_*` classname. This is a playable shell; human aim balance and weapon behavior require a live test.

Build with `map_build(preset="full")`, then inspect `check_map` and open `game_screenshot` frames. `mode_setup` does not promise that native matchmaking config or Workshop metadata selects a mode; the returned launch command is the source of truth for local testing.

## By hand

A mode is cvars plus entities: `mode_setup` or a script's `ServerCommand` on round start for `mp_*` cvars; team spawns `info_player_terrorist`/`info_player_counterterrorist` (or `info_deathmatch_spawn`), loadouts with `game_player_equip`, checkpoints with `trigger_teleport` + `info_teleport_destination`, surf ramps as `extrude` wedges with steep sides (over ~45° players slide). Rules no cvar has: `scripting`, `abilities`.
